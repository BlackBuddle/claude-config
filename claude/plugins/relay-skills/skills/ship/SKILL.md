# 출하 점검 (/ship)

생각은 garrytan/gstack 의 `/ship` 에서 가져왔다 (2026-11-18 사용자 결정: 흡수).
점검만 한다. 커밋과 push는 마지막에 사용자의 확인을 받은 뒤에 한다.

## 규칙
- 항목마다 명령을 실제로 실행한다. 실행하지 못한 항목은 "실행하지 못함"으로 쓴다. 추측으로 "통과"를 쓰지 않는다.
- 실패 항목이 있으면 고치지 않는다. 표와 원인을 보이고 멈춘다. 고칠지는 사용자가 정한다.
- 긴 출력은 조용한 옵션으로 실행한다 (예: `pytest -q --tb=short`).

## 점검 순서
1. **원격 먼저**: `git fetch` 를 실행한다. 원격이 앞서 있으면 멈추고 알린다. 다른 세션의 같은 변경과 충돌할 수 있다.
2. **변경 범위**: `git status --short` 와 `git diff --stat` 를 보인다. 요청과 관계없는 파일이 있으면 표시한다.
3. **비밀 정보**: 변경 파일에 `.env`, `.credentials.json`, 키 파일이 없는지 본다. diff 에서 `api_key`, `token`, `password`, `secret` 같은 값 대입을 찾는다. 찾으면 줄 번호만 쓰고 값은 쓰지 않는다.
4. **테스트·린터·타입 검사**: 프로젝트에 있는 것만 실행한다. 각각 "통과 / 실패 / 없음 / 실행하지 못함" 중 1개로 쓴다.
5. **결정 기록**: 이번 변경에 사용자 결정이 있었으면 `docs/결정_기록.md` 에 들어갔는지 본다.
6. **문서**: 사용법·설치·명령이 바뀌었으면 README 와 관련 문서가 같이 바뀌었는지 본다.
7. **인계**: 단계가 끝났으면 ROADMAP 의 진행 상태가 맞는지 본다.

|---|---|---|
| 원격 | 같음 / 앞섬 | `git status -sb` 첫 줄 |
| ... | ... | ... |

표 아래에 1줄로 쓴다: "커밋·push 준비 됨" 또는 "멈춤: <실패 항목>".
준비가 되었으면 커밋 메시지 초안 1줄을 보이고, 커밋과 push를 할지 묻는다.
