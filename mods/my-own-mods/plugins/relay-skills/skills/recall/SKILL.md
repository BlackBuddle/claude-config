# 지난 결정·작업 찾기 (/recall)

생각은 thedotmack/claude-mem 과 vectorize-io/hindsight 의 "색인 먼저, 내용은 필요할 때"에서 가져왔다 (2026-11-18 사용자 결정: 흡수).
새로 기록하지 않는다. 이미 있는 문서와 세션 기록만 찾는다. 외부로 보내지 않는다.

## 규칙
- 근거 없이 답하지 않는다. 답마다 출처(파일 경로 또는 세션 이름)와 날짜를 붙인다.
- 원문은 짧게 인용한다. 결정은 `결정_기록.md`의 "답 (원문)"을 그대로 쓴다.
- 못 찾으면 "찾지 못했다"라고 쓰고, 찾은 범위를 쓴다. 추측으로 채우지 않는다.
- 비밀 정보(키, 토큰, 비밀번호)가 결과에 섞이면 값은 쓰지 않는다.

## 찾는 순서 (싼 것부터)
1. **결정 기록**: 현재 프로젝트의 `docs/결정_기록.md`를 Grep 한다. 없거나 못 찾으면 `C:\Users\KCCISTC\Desktop` 아래 모든 `결정_기록.md`(glob `**/결정_기록.md`)와 `C:\Users\KCCISTC\claude-config\docs\결정_기록.md`를 Grep 한다.
2. **인계·진행 문서**: 같은 범위의 `HANDOFF.md`, `ROADMAP.md`를 Grep 한다.
3. **git 기록**: 관련 저장소에서 `git log --oneline -i --grep=<검색어> -20` 을 실행한다.
4. **세션 기록**: 1~3에서 못 찾았거나, 문서에 쓰지 않은 대화를 찾을 때만 한다.
   - 앱의 세션 기록 검색 도구(`search_session_transcripts`)가 있으면 그것을 쓴다. 지연 도구면 ToolSearch 로 먼저 불러온다.
   - 도구가 없으면 `~/.claude/projects/*/*.jsonl` 을 Grep 한다. 범위를 현재 프로젝트 폴더로 먼저 좁힌다. 기록이 수 GB라 전체 Grep 은 마지막에만 한다.
5. 찾은 원문이 300줄을 넘으면 `summarizer` 에이전트에게 요약을 맡긴다.

검색어는 2~3개로 바꿔 본다 (예: "접기", "fold", "완료·유휴").

| 날짜 | 내용 | 출처 |
