# 인계 문서 만들기

다음 세션이 이 세션의 대화를 보지 않고도 바로 이어서 일할 수 있게, 프로젝트 루트의 `HANDOFF.md` 하나를 새로 쓴다. 양식은 `docs/통합_작업방식.md` 8절의 "HANDOFF.md 양식"과 같다. 이전 `HANDOFF.md`는 덮어쓴다(최신 1개만 둔다).

## 규칙
- `HANDOFF.md` 하나만 쓴다. 다른 파일은 고치지 않고 커밋하지 않는다.
- "완료"는 이 세션에서 실제로 실행한 명령의 결과를 본 것만 적는다. 명령과 결과 한 줄을 같이 적는다.
- 실행하지 않았거나 결과를 못 본 것은 "확인하지 못한 것"에 적는다. 추측으로 "되었을 것"이라고 적지 않는다.
- 같은 종류의 증거는 한 줄로 묶는다. 예: "`claude plugin test` → session-board 91개 통과".
- push·삭제·원격 작업은 "미리 승인된 것"에 적지 않는다.
- 모르는 것은 모른다고 적는다. 문장은 짧게, 한 문장에 한 가지만 쓴다.

## 순서
1. 이 세션에서 한 일을 되짚는다. `git status`, `git log -1`, `git diff --stat`으로 변경과 마지막 커밋을 확인한다.
2. 하위 에이전트나 자식 세션이 실행 중인지 확인한다. 이 앱에서 쓸 수 있으면 `list_sessions`(linked: true)로 본다. 실행 중이면 "꼭 알아야 할 사실"에 적고 보관하지 말라고 쓴다.
3. 프로젝트 루트의 `HANDOFF.md`를 아래 양식으로 쓴다.
4. 파일 경로와 아래 3줄만 사용자에게 알린다.
   - 숫자 한 줄: `완료 N · 미완료 N · 확인하지 못한 것 N`
   - 첫 행동: 다음 세션이 가장 먼저 할 일 하나
   - 자식 세션: `실행 중 N개` 또는 `없음` 또는 `확인 못 함`

## 양식
```markdown
# 인계 (YYYY-MM-DD, <단계 또는 작업 이름>)

## 지금 위치
- 단계: <이름> — <진행 중 / 판정 대기 / 완료>
- 마지막 커밋: <해시> <제목> (push: 함/안 함)
- 작업 트리: <깨끗함 / 커밋 안 한 변경과 이유>
- 자동 시험: <xx/xx 통과> (명령: <명령>)

## 완료 (증거 있음)
- <한 일> — `<실행한 명령>` → <결과 한 줄>

## 다음 세션이 할 일 (순서대로)
1. <가장 먼저 할 일 하나>

## 미리 승인된 것 (다음 1개 세션만 유효)
- <없으면 "없음">

## 사용자 확인이 필요한 것
- <결정이 필요한 것>

## 확인하지 못한 것
- <실행하지 않았거나 결과를 못 본 것>

## 꼭 알아야 할 사실 · 주의
- <최근 결정, 함정, 진행 중인 것, 실행 중인 자식 세션>

## 코드 위치
- <파일>: <무엇이 있나>

## 노력 수준·모델 제안
- <다음 작업 종류와 권장 노력 수준>
```
