# 검토 선택표

작성: 2026-11-14. 상황 1개에 명령 1개를 고른다. 표에 없는 상황은 사용자에게 묻는다.

## 0. 공통 규칙

- Claude는 작업 끝에 검토 명령 1개를 제안한다. 사용자가 승인하면 실행한다.
- 검토는 노력 수준 high의 작업이다. 실행 전에 노력 수준을 다시 제안한다.
- 검토는 테스트와 실제 장치 시험을 대신하지 않는다.
- 2개 이상의 줄이 맞으면 표에서 아래쪽 줄을 따른다 (더 엄격한 쪽).

## 1. 코드 검토

| 상황 | 명령 |
|---|---|
| 변경 1건을 끝냈다 (평소) | `/ponytail-review` |
| 큰 변경을 끝냈다. 병합이나 배포 전이다 | `/code-review high` |
| 외부 입력, 네트워크, 인증, 파일 삭제를 다루는 코드다 | `/security-review` |
| 단계 1개를 끝냈다. 저장소 전체를 점검한다 | `/ponytail-audit` |
| 중복이 보인다. 코드가 길어졌다 | `/simplify` |
| 장치(Jetson, 로봇)를 움직이는 코드다 | `/code-review high` + 실제 장치 시험 |
| 문서만 고쳤다. 1줄만 고쳤다 | 검토하지 않는다 |

## 2. 설계 검토 (EGM, 잠정)

주의: EGM(google/elephant-goldfish-model, 플러그인 `egm@egm`)은 2026-11-14에 설치했다. 아직 실행하지 않았다. 벗(Beot) 재설계안으로 시험한 뒤 이 절을 고친다.

| 상황 | 명령 |
|---|---|
| 크기 S 프로젝트 | 검토하지 않는다 |
| 크기 M·L의 새 설계 문서를 썼다 | 구현 전에 `/egm:egm-review <문서>` 1회 |
| 설계 문서를 크게 고쳤다 | `/egm:egm-review <문서>` 다시 1회 |
| 단계 1개를 끝냈다. 오래 쉰 프로젝트를 다시 시작한다 | `/egm:egm-drift-report <폴더>` |
| 설계 문서가 코드보다 낡았다 | 멈춘다. 사용자에게 재확인받는다. 문서 갱신을 요청한다 |

- 설계 문서가 절대 기준이다. ROADMAP.md와 HANDOFF.md는 참고 자료다.
- 검토 지적과 사용자의 결정은 `docs/결정_기록.md`에 쓴다.
