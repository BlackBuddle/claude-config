# 노력 수준 · 모델 운용 규칙 (범용)

> 모든 프로젝트에 적용하는 규칙. 프로젝트 이름·단계 이름 등 고유 내용은 넣지 않았다.
> **위치**: `~/.claude/docs/노력수준_모델운용.md` (전역). 전역 `CLAUDE.md`의 "Effort level · model" 절이 요약이고, 이 문서가 전체 내용이다. 프로젝트에 복사하지 않는다.
> 프로젝트 `CLAUDE.md`에는 기본 모델과, 고친 기준표가 있으면 그 표만 적는다.

## 0. 한눈에

1. **기본 모델 하나**를 정하고, 그 모델에서는 **노력 수준만 바꿔** 작업한다.
2. **모든 세션**(총괄·작업·하위 세션)은 작업을 시작하기 전에 **필요한 노력 수준을 먼저 제시**한다.
3. 사용자가 노력 수준을 바꾸고 **확인해 줘야만** 진행한다. 확인이 없거나 맞지 않으면 **진행하지 않는다**.
4. 기본 모델로 부족한 일은 **별도 세션**에서 잠시 다른 모델로 하고, 끝나면 기본 모델로 돌아온다.

## 1. 왜 이렇게 하나

- 노력 수준이 높을수록 시간·비용이 커진다. 일에 맞게 낮추고 올리면 품질은 지키고 비용은 줄인다.
- 세션은 자기 노력 수준을 확실히 알 수 없다. 그래서 "사용자 확인"을 진행 조건으로 삼는다.
- 모델을 자주 바꾸면 이전 맥락이 끊기고 혼란스럽다. 기본 모델을 고정하고 **노력 수준만** 바꾸는 편이 안정적이다.

## 2. 기본 모델 고르기

| 상황 | 기본 모델 추천 |
|---|---|
| 구현·문서 작업이 대부분, 세션이 많고 길다 | 중간 단가 모델 (예: Sonnet 계열) |
| 설계 판단·검토가 대부분, 세션이 적다 | 상위 모델 (예: Opus 계열) |
| 긴 자료를 읽고 줄이기만 하는 일 | 가장 싼 모델 (예: Haiku 계열) — 요약 에이전트로 분리 |

기본 모델은 프로젝트 시작 때 **한 번** 정하고 기록한다. 바꾸려면 사용자 결정이 필요하다.

## 3. 노력 수준 기준표

| 수준 | 맞는 작업 | 예 |
|---|---|---|
| **low** | 문서·진행표·인계 갱신, 목록·요약, 단순 수정, 커밋 | 진행 상태 한 줄 고치기 |
| **medium** | 일반 구현, 자동 시험 작성, 데이터 변환 | 모듈 하나 만들기 |
| **high** | 설계 판단, 평가·통계 코드, 코드·설계 검토, 두 번 이상 실패한 디버깅, 단계 심사 | 기준 통과 여부 판정 |
| **xhigh 이상** | 별도 세션(상위 모델)으로 넘긴다 | 숙의, 세 번 실패, 계획 변경 |

> 기준표는 프로젝트에 맞게 고쳐도 된다. 고친 표를 `CLAUDE.md`에 적는다.

## 4. 시작 전 절차 (모든 세션 공통)

1. 세션이 작업 목록을 보고 **필요한 노력 수준과 이유**를 한두 줄로 제시한다.
   - 제시하기 전에 **현재 세션의 모델을 확인**한다. 모델 이름과 수준을 같이 쓴다.
   - 예: `이번 작업: 모듈 구현 + 시험 → Sonnet 5.5 기준 medium`
   - 3절의 기준표는 프로젝트의 기본 모델 기준이다. 상위 모델에서는 1단계 낮게 제시한다. 같은 문제가 반복해서 실패하면 다시 올린다.
   - 세션의 모델이 프로젝트의 기본 모델과 다르면 그 사실을 먼저 알린다.
2. **사용자가 노력 수준을 바꾼 뒤 "변경함"(또는 같은 뜻)이라고 알려 준다.**
3. 확인을 받으면 진행한다. 받지 못하면 **어떤 작업도 시작하지 않는다** (읽기만 허용).
4. 작업 도중 수준이 맞지 않다고 판단하면 **멈추고** 다시 제시한다.
   - 예: medium으로 시작했는데 설계 판단이 필요해졌다 → 멈추고 high를 제안.
   - 예: 같은 문제를 세 번 고쳐도 안 된다 → 멈추고 상위 모델 별도 세션을 제안.
5. 작업 종류가 바뀔 때(구현 → 심사 등)도 새로 제시한다.

## 5. 모델을 바꿔야 할 때 (별도 세션 방식)

| 조건 | 처리 |
|---|---|
| 기본 모델로 부족한 판단(계획 검토, 되돌릴 수 없는 결정, 세 번 실패) | 별도 세션을 만들어 상위 모델로 작업 → 결과를 문서에 기록 → 기본 모델 세션으로 복귀 |
| 긴 자료를 읽고 요약만 필요 | 요약 전용 에이전트(가장 싼 모델)에 맡김 |

규칙:
- **세션 안에서 모델을 바꾸지 않는다.** 이유: 새 모델이 대화 전체를 다시 읽어 토큰이 낭비된다. 세션의 모델은 사용자만 바꾼다. 에이전트는 차이를 발견하면 알린다.
- 필요한 모델이 현재 모델과 다를 때:
  - 큰 작업(도구 호출 약 5회 이상, 또는 브랜치·문서·빌드 같은 자기 결과물이 남는 작업): 총괄 세션 아래에 별도 세션을 제안한다. 사용자가 승인한 뒤에 연다.
  - 작은 작업: 현재 모델로 한다.
  - 읽기만 하는 조사: 서브에이전트로 한다 (모델과 노력 수준은 일에 맞춘다).
- 별도 세션에는 HANDOFF 양식의 지시문과 완료 기준을 준다. 결과를 확인한 뒤에 완료를 보고한다.
- 별도 세션마다 맡는 파일을 따로 정한다. 두 세션이 같은 파일을 동시에 고치지 않는다.
- 별도 세션을 **만들 때** 모델과 노력 수준을 시작 설정에 **명시**한다.
- 별도 세션의 결과는 대화가 아니라 **문서(파일)**로 돌려받는다.
- 별도 세션이 끝나면 닫고, 기본 모델 세션에서 이어 간다.
- 모델을 바꾼 이유와 결과를 프로젝트의 결정·구현 기록에 한 줄 남긴다.

## 6. CLAUDE.md에 붙일 블록

```markdown
## 노력 수준 · 모델 운용
- 기본 모델: <모델 이름>. 이 모델에서는 노력 수준만 바꾼다.
- 모든 세션(하위 세션 포함)은 작업 시작 전에 필요한 노력 수준을 제시한다.
- 사용자가 노력 수준을 바꾸고 확인해 주기 전에는 작업을 시작하지 않는다 (읽기만 허용).
- 작업 도중 수준이 맞지 않으면 멈추고 다시 제시한다. 작업 종류가 바뀔 때도 새로 제시한다.
- 노력 수준 기준: low = 문서·진행표·커밋 / medium = 일반 구현·시험 / high = 설계 판단·평가·검토·심사·반복 실패 디버깅 / xhigh 이상 = 별도 세션(상위 모델).
- 기본 모델로 부족하면 별도 세션에서 잠시 다른 모델로 작업하고 기본 모델로 돌아온다. 하위 세션 생성 시 모델·노력 수준을 명시한다.
```

## 7. 자주 하는 실수

| 실수 | 바로잡기 |
|---|---|
| 확인 없이 "아마 이 정도 수준이겠지" 하고 시작 | 확인을 받을 때까지 읽기만 한다 |
| 하위 세션에 규칙을 안 알림 | 하위 세션 시작 문구에 이 블록을 포함한다 |
| 어려워졌는데 그대로 진행 | 멈추고 수준을 다시 제시한다 |
| 모델을 수시로 바꿈 | 기본 모델 고정, 바꾸는 건 별도 세션으로만 |
