# 디자인 · 모션 스킬 선택표

작성: 2026-11-14. 상황 1개에 스킬 1개를 고른다. 표에 없는 상황은 사용자에게 묻는다.

주의: 아래 스킬은 웹(HTML/CSS/React)용이다. PyQt에는 원칙만 적용한다. 코드는 그대로 쓸 수 없다.

스킬 위치: `stageshow`, `design-clash`, `nothing-design`이 로컬(`~/.claude/skills`)이다. `frontend-design`은 공식 플러그인이다 (`frontend-design:frontend-design`). 나머지는 계정 스킬이다. 계정 스킬을 직접 부를 때는 `/anthropic-skills:<이름>`으로 쓴다.

## 2-1. 발표 슬라이드

도구: Slides 아티팩트(`slides` 스킬)가 기본이다. 파일이 필요하면 `pptx`다. 어느 도구로 만들든 아래 규칙 3개를 따른다. 생각은 zarazhangrui/frontend-slides에서 가져왔다 (2026-11-18 사용자 결정: 흡수).

1. **밀도 모드를 먼저 정한다.** 발표용(화면에 띄우고 말한다): 슬라이드 1장에 생각 1개, 1~3줄, 큰 글자. 읽기용(나눠 주고 읽는다): 4~8줄 또는 카드 4~6개. 사용자가 말하지 않으면 발표용이다. 내용이 넘치면 글자를 줄이지 않고 슬라이드를 나눈다.
2. **표지 3안을 먼저 보인다.** 전체를 만들기 전에 표지 슬라이드만 3안(무난한 안 1, 대담한 안 1, 의외의 안 1)으로 보이고 고르게 한다. 미리보기에 "Option A", 파일 이름, 템플릿 이름 같은 내부 문구를 쓰지 않는다. 실제 제목과 내용을 넣는다.
3. **HTML로 직접 만들 때 (1920×1080 스테이지).** 슬라이드를 1920×1080 고정 크기로 만들고 화면에 맞게 통째로 확대·축소한다. 슬라이드 전환은 `display`가 아니라 `visibility`·`opacity`·`pointer-events`로 한다. 음수 `clamp()`는 `calc(-1 * clamp(...))`로 쓴다.

## 3. 요청이 모호할 때의 기본값

- "새로 만들어 줘" (앱 화면) → `frontend-design`
- "새로 만들어 줘" (사이트·페이지) → `hallmark`
- "이거 고쳐 줘 / 봐 줘" → `impeccable`
- "움직이게 해 줘" → `animate`
- 2개 이상이 맞으면 사용자에게 1번 묻는다. 권장 1개와 이유를 붙인다.

## 6. 근거: 비교 시험 (2026-11-14)

같은 지시문으로 4개 스킬을 실행하고 결과를 브라우저에서 비교했다. 각 1회 실행이라 편차가 있을 수 있다.

| 시험 | 1위 | 2위 | 3위 | 4위 |
|---|---|---|---|---|
| 1차: 새 RL 관제 대시보드 | taste | frontend-design | oh-my-design | ui-ux-pro-max |
| 2차: Beot 앱 개선 (취향 지시 있음) | frontend-design ≈ taste | | oh-my-design | ui-ux-pro-max |
| 3차: 새 로봇팔 티칭 앱 (스타일 지시 없음) | frontend-design | taste ≈ oh-my-design | | ui-ux-pro-max |

- frontend-design: 3번 모두 1~2위. 가장 싸다 (약 10만~12만 토큰).
- taste: 결과 편차가 크다. 비용이 가장 크다 (약 17만~20만 토큰).
- 기존 앱 개선은 스킬보다 지시문이 결과를 더 크게 결정했다.
- 배포 페이지 (JetDeck·Beot): taste = 첫인상·개성, hallmark = 깔끔한 기능 설명. 사용자 평가는 "둘 다 나쁘지 않다".
