# 하이쿠 요약 시스템 — 서브에이전트로 긴 자료 읽기

> 긴 파일·로그·검색 결과를 **값싼 Haiku 서브에이전트(`summarizer`)** 가 대신 읽고, 메인(Opus/Sonnet)은 **요약만** 받아 쓰는 방식.
> **쓰는 법**: 이 파일을 Claude Code 에 주고 "`하이쿠_요약_시스템.md` 를 읽고 2장 설치를 해 줘" 라고 하면 끝.
> (직접 할 경우: 2장의 두 파일만 만들면 됨 → 앱 재시작 또는 새 세션부터 적용)

---

## 0. 한눈에

```
사용자 질문
   │
   ▼
메인 모델 ── 짧은 자료(약 300줄 미만, 파일 1개) ──▶ 직접 읽고 답함
   │
   └─ 긴 자료(약 300줄 이상 / 여러 파일 / 긴 로그·검색 결과)
         │
         ▼
   summarizer (Haiku, 읽기 전용: Read·Glob·Grep)
         │  결론 · 근거 위치(파일:줄) · 확인 필요한 점
         ▼
   메인 모델 ── 요약 기반 답변 (첫 줄에 "📋 summarizer 사용" 표시)
```

- **왜?** 긴 원문이 메인 대화에 들어가면, 이후 매 턴마다 그 원문이 다시 전송돼 토큰 비용이 쌓임. 서브에이전트는 **자기 창에서 읽고 요약만 돌려주므로** 메인 대화가 가벼워짐
- **Haiku 인 이유**: 읽고 줄이는 일은 큰 모델이 필요 없음 → 단가가 가장 싼 모델로 처리
- 구성 요소는 딱 2개: ① 에이전트 정의 파일 ② "언제 쓰라" 는 규칙(CLAUDE.md)

## 1. 적용 범위 고르기

| 범위 | 에이전트 파일 위치 | 규칙 위치 | 언제 |
|---|---|---|---|
| **전역 (추천)** | `%USERPROFILE%\.claude\agents\summarizer.md` | `%USERPROFILE%\.claude\CLAUDE.md` | 모든 프로젝트에서 쓰고 싶을 때 |
| 프로젝트 한정 | `<프로젝트>\.claude\agents\summarizer.md` | `<프로젝트>\CLAUDE.md` | 특정 프로젝트만 / 팀과 공유할 때 |

- 같은 이름이 둘 다 있으면 **프로젝트 쪽이 우선**
## 2. 설치 (파일 2개)

### 2-1. 에이전트 정의 — `summarizer.md`

```markdown
---
name: summarizer
description: 긴 파일·로그·검색 결과를 읽고 핵심만 요약해 메인에 돌려준다
tools: Read, Glob, Grep
model: haiku
---

너는 요약 담당이다. 받은 자료를 끝까지 읽고
결론, 근거가 된 파일 위치, 확인이 더 필요한 점만 짧게 한국어로 정리해 돌려준다.
```

| 항목 | 의미 |
|---|---|
| `name` | 호출 이름. 규칙(2-2)에서 이 이름으로 부름 |
| `description` | 메인 모델이 "언제 이 에이전트를 쓸지" 판단하는 근거. 구체적으로 쓸수록 잘 불림 |
| `tools` | **읽기 전용 3종만** 허용 → 실수로 파일을 고치거나 명령을 실행할 수 없음 |
| `model: haiku` | 최신 Haiku 를 자동 선택 (버전 번호 안 써도 됨) |
| 본문 | 서브에이전트의 시스템 프롬프트. 돌려줄 형식을 고정 |

### 2-2. 사용 규칙 — `CLAUDE.md` 에 추가

```markdown
## Tokens
- Read only the needed parts of long files
- For long files/logs/search results (roughly 300+ lines or multiple files), delegate reading to the `summarizer` agent and use only its summary. Handle short content directly
- When a reply is based on `summarizer` output, put `📋 summarizer 사용 (요약 기반 답변)` on the very first line of that reply
```

- 규칙을 영어로 쓰는 이유: 모델이 지시를 더 일관되게 따르고 토큰도 약간 적음 (한국어로 써도 동작은 함)
- **표시 줄(📋)** 은 "이 답은 원문이 아니라 요약을 보고 한 답" 임을 사용자가 알게 하려는 것 → 중요한 판단이면 원문 확인 요청 가능

### 2-3. PowerShell 로 한 번에 설치 (전역)

```powershell
$dir = "$env:USERPROFILE\.claude\agents"
New-Item -ItemType Directory -Force $dir | Out-Null
$text = @'
---
name: summarizer
description: 긴 파일·로그·검색 결과를 읽고 핵심만 요약해 메인에 돌려준다
tools: Read, Glob, Grep
model: haiku
---

너는 요약 담당이다. 받은 자료를 끝까지 읽고
결론, 근거가 된 파일 위치, 확인이 더 필요한 점만 짧게 한국어로 정리해 돌려준다.
'@
# UTF-8 (BOM 없음) 으로 저장 — PowerShell 5.1 의 Out-File utf8 은 BOM 을 붙임
[IO.File]::WriteAllText("$dir\summarizer.md", $text, (New-Object Text.UTF8Encoding $false))
```

- `CLAUDE.md` 는 기존 내용이 있을 수 있으니 **2-2 블록을 직접 붙여 넣기** (덮어쓰기 금지)
- 설치 후 **새 세션**을 열어야 반영됨

## 3. 확인 방법

1. 새 세션에서 300줄 넘는 파일을 주고 "이 파일 요약해 줘"
2. 답 첫 줄에 `📋 summarizer 사용 (요약 기반 답변)` 이 보이면 성공
3. 대화창에 `summarizer` 에이전트 실행 표시가 뜨는지도 확인
4. 짧은 파일(수십 줄)은 **직접 읽어야 정상** — 이때 📋 줄이 없어야 함

## 4. 쓸 때 / 안 쓸 때

| 상황 | summarizer | 이유 |
|---|---|---|
| 긴 로그에서 에러 원인 찾기 | ✅ | 원문은 길고 필요한 건 몇 줄 |
| 여러 파일에 걸친 구조 파악 | ✅ | 메인이 다 읽으면 대화가 무거워짐 |
| 긴 검색(grep) 결과 정리 | ✅ | |
| 짧은 파일 1개 읽기 | ❌ | 에이전트 띄우는 비용이 더 큼 |
| **코드를 고쳐야 하는 부분** | ❌ (위치만 ✅) | 고칠 줄은 메인이 직접 정확히 읽어야 함 → summarizer 로 위치(파일:줄)만 찾고, 그 부분만 메인이 Read |
| 정확한 숫자·문구가 중요한 답 | ⚠️ | 요약은 세부를 잃을 수 있음 → 원문 해당 부분 재확인 |

## 5. 직접 시키는 법 (규칙이 없어도 됨)

- "`summarizer` 로 `logs/` 폴더 요약해 줘"
- "summarizer 로 이 프로젝트에서 시리얼 통신 코드가 어디 있는지만 찾아 줘"
- 앱에 따라 서브에이전트를 **자동으로 잘 안 쓰는** 경우가 있음 → 이름을 직접 부르면 확실함

## 6. 변형 · 조정

- **요약 형식 바꾸기**: 2-1 본문을 수정. 예) `- 결론 3줄 이내 / - 근거: 파일:줄 목록 / - 확인 필요` 처럼 틀을 주면 더 일정해짐
- **기준 줄 수 조정**: 2-2 의 `300+ lines` 를 200/500 등으로
- **영어 요약**: 본문의 "한국어로" → "in English"
- **다른 용도 에이전트 추가**: 같은 형식으로 파일만 추가 (예: `log-reader.md`, `test-runner.md`). `tools` 는 필요한 최소만

## 7. 문제 해결

| 증상 | 원인 · 해결 |
|---|---|
| summarizer 가 아예 안 불림 | 새 세션인지 확인 / 파일 위치·이름 확인 / 5장처럼 이름을 직접 부르기 |
| 에이전트 목록에 없음 | front matter(`---` 사이) 형식 오류. 첫 줄이 정확히 `---` 인지, BOM·들여쓰기 없는지 확인 |
| 한글이 깨짐 | 파일을 **UTF-8 (BOM 없음)** 으로 저장 (`Set-Content` 기본값은 ANSI → 2-3 의 `WriteAllText` 방식 사용) |
| 요약이 부정확 | 본문에 "모르면 모른다고 쓸 것, 추측 금지" 추가 / 중요한 부분은 원문 재확인 |
| 짧은 파일도 매번 넘김 | 2-2 의 "Handle short content directly" 문구 유지, 기준 줄 수 올리기 |
