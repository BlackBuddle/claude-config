# 결재함 설계 (PLAN)

작성: 2026-11-15. 판: 2 (EGM 검토 반영). 상태: 승인됨 (2026-11-15). 크기: M.
결정은 `(결정 2026-11-15, Qn)` 또는 `(결정 2026-11-15, Dn)`으로 표시한다. 원문은 [docs/결정_기록.md](docs/결정_기록.md)에 있다.
검토 보고서: EGM 통합 보고서 (2026-11-15). 이 문서의 반영 번호 R1~R13은 그 보고서의 "반영할 것"이다.

## 1. 목적

- 여러 프로젝트의 여러 세션이 사용자를 기다린다.
- 사용자는 "어느 세션이 무엇을 기다리는가"를 한곳에서 본다.
- 결정은 그 세션의 대화에서 한다. 결재함은 보여주고 그 세션으로 보낸다.

## 2. 구성 요소 (R1)

| 요소 | 무엇인가 |
|---|---|
| 앱 | Claude 데스크톱 앱 (Code 탭). 터미널의 `claude`도 같은 mod를 쓴다 |
| mod | `~/.claude/skills/decision-rack/`의 플러그인 hooks 모듈. **세션마다 1개**가 그 세션 안에서 돈다 |
| 대기열 폴더 | `~/.claude/decisions/v2/`. 모든 세션의 mod가 같은 폴더를 읽는다 (D3) |
| 패널 | 각 세션 화면 오른쪽의 "결재함". mod가 대기열 폴더를 2초마다 읽어 그린다 |
| 띠 | 프롬프트 바로 위의 줄 (`AbovePrompt`). 패널을 닫으면 띠의 맨 위(ponytail 줄 위)에 `● 결재 1  ● 알림 1 …… 결재함` (`결재함`은 여는 글자 단추)를 보인다 (ponytail 줄과 같은 모양, 0인 종류 생략). 상태 줄은 누를 수 없어서 띠로 바꿨다 (결정 2026-11-15) |
| 세션 번호 | 엔진의 세션 id (대화 기록 파일의 이름). 파일 이름에는 앞 8자를 쓴다 |

## 3. 지금 구조 (판 1까지)

| 일 | 누가 한다 |
|---|---|
| 칸을 만든다 | 세션의 AI가 결정 파일을 Write로 쓴다 |
| 칸에 세션 번호를 쓴다 | mod (Write를 가로챈다) |
| 칸을 내린다 | mod: 그 세션에 사용자가 아무 입력이나 하면 내린다 |
| 파일을 지운다 | 세션의 AI (mod가 넣는 알림 글을 받고) |
| 아직 기다리면 다시 올린다 | 세션의 AI (새 번호로) |
| AI가 잊은 칸을 찾는다 | mod: 마지막 답에서 "사용자를 기다리는" 같은 글자 표시를 찾는다 |

## 4. 실제로 생긴 문제 (2026-11-15 이 설계를 만든 세션의 기록)

| # | 문제 | 원인 |
|---|---|---|
| 1 | 세션이 기다리는데 칸을 올리지 않았다 (프로젝트 Beot-src) | AI가 규칙을 잊었다 |
| 2 | mod가 대신 만든 칸의 질문이 "사용자를 기다리는 것"이다. 내용이 없다 | 글자 탐지가 제목 줄을 골랐다 |
| 3 | 아무 입력이나 하면 칸이 사라진다 | mod는 입력이 그 질문의 답인지 모른다 |
| 4 | 취소된 결정이 남았다 | AI가 같은 파일을 고쳐 썼다. 지우는 일을 잊었다 |
| 5 | 칸이 먼저 뜨고 질문은 나중에 보였다 | 칸을 쓴 직후에 대화 압축이 시작되었다 |
| 6 | 칸을 눌러도 세션으로 가지 않았다 | mod 없이 시작한 세션이 칸을 올렸다 |
| 7 | 질문이 대화와 칸에 따로 있다. 내용이 어긋난다 | 원본이 2개다 |
| 8 | 결정 1개에 도구 호출이 3~4번 든다 | 칸의 일생을 AI가 관리한다 |

공통 원인: **칸의 일생을 AI의 기억에 맡겼다.** AI는 잊는다. mod는 답의 뜻을 모른다.

## 5. 원칙

1. **칸의 뜻**: "이 세션이 지금 사용자를 기다린다". 턴이 끝날 때 다시 판정한다. (결정 2026-11-15, Q0)
2. **세션마다 기다림 칸 1개와 확인 칸 1개.** 여러 기다림은 기다림 칸 1개에 모은다. 혼자 정한 것은 확인 칸 1개에 줄로 모은다. (결정 2026-11-15, Q5)
3. **원본은 대화 1개다.** 칸은 대화에서 뽑는다. AI는 칸의 파일을 쓰지 않는다. (결정 2026-11-15, Q1)
4. **칸의 일생은 mod가 정한다.** 파일은 지우지 않는다. 상태를 덮어쓴다. (결정 2026-11-15, Q1·D1)
5. **파일마다 쓰는 쪽은 주인 mod 1개다.** 예외는 1개: 다른 세션의 패널이 확인 칸에 `state: "closed"`만 쓴다.

## 6. 칸의 상태와 파일 (R2, R3)

### 6.1 상태

| 상태 | 패널 모양 | 상태 줄 개수 | 누가 쓰나 | 언제 |
|---|---|---|---|---|
| `waiting` | 진하게 | 센다 | 주인 mod | 턴 끝·세션 시작에 신호가 있다. 선택 카드가 떴다. 중단된 턴 뒤 (`busy`였으면) |
| `busy` | 흐리게, "진행 중" | 세지 않는다 | 주인 mod | 사용자가 그 세션에 입력했다. 선택 카드에 답했다 (결정 2026-11-15, Q3) |
| `closed` | 보이지 않는다 | 세지 않는다 | 주인 mod (확인 칸은 다른 세션의 패널도) | 사용자 입력으로 시작한 턴이 신호 없이 끝났다 (D4). 사용자가 세션을 끝냈다 (D2). 확인 칸의 "확인"을 눌렀다 |

- "칸을 내린다"는 `closed`를 쓰는 일이다. 파일은 지우지 않는다. (D1)

### 6.2 파일

- 기다림 칸: `~/.claude/decisions/v2/<세션 번호 앞 8자>-wait.json`
- 확인 칸: `~/.claude/decisions/v2/<세션 번호 앞 8자>-report.json`
- 파일 이름에 프로젝트 이름을 쓰지 않는다. 이름은 16진수와 `-`뿐이다. 패널은 이 이름 모양만 읽는다: `^[0-9a-f]{8}-(wait|report)\.json$`.

```json
{
  "state": "waiting",
  "raisedAt": 1763211600000,
  "kind": "request",
  "question": "<첫 줄>",
  "background": ["<나머지 줄>"],
  "options": ["<선택지>"],
  "project": "<프로젝트 폴더 이름>",
  "root": "<프로젝트 키>",
  "session": "<세션 번호>",
  "link": "claude://claude.ai/epitaxy/local_<앱 세션 id>"
}
```

- `kind`: `request`(결재, 빨강) · `notice`(알림, 노랑) · `report`(확인, 초록).
- 확인 칸은 `question` 대신 `lines`(혼자 정한 것의 줄 목록)를 쓴다.
- `raisedAt`: `waiting`이 새로 시작된 시각. 확인 칸은 첫 줄을 더한 시각. 알림 키와 칸의 시간 표시에 쓴다.

## 7. 칸을 만드는 신호와 판정 (R4, R5, R6)

### 7.1 신호

| 순서 | 신호 | 칸에 들어가는 것 | 확인 상태 |
|---|---|---|---|
| 1 | 선택 카드 (`AskUserQuestion` 호출, 답하지 않은 것) | 첫 질문, 그 선택지 | 확인됨 (엔진 타입). 답한 카드는 결과(`text`)가 있어 세지 않는다 |
| 2 | 앱의 질문 상자 (`mcp__ccd_turn__wrap_up`의 질문 필드) | 질문(`ask`), 버튼 글(`actions[].label`) | 확인됨 (도구 스키마, 2026-11-15) |
| 3 | 답의 표시 줄: 줄 맨 앞(글머리표 뒤)의 `결재:` · `알림:` | 그 줄의 글 | 확인됨 |
| 4 | 마지막 답의 마지막 줄이 `?`로 끝난다 | 그 줄 | 확인됨. 신호 1~3이 없을 때만 (결정 2026-11-15, Q6) |
| — | 확인 신호: 줄 맨 앞의 `확인:` | 확인 칸의 줄 | 기다림 칸을 만들지 않는다 |

### 7.2 판정 함수 `sync()`

- 입력: 그 세션의 마지막 턴(마지막 사용자 입력 뒤)의 assistant 글과 도구 호출 (`$.session.messages()`). 그래서 상태를 따로 저장하지 않는다.
  - 표시 줄(`결재:`·`알림:`·`확인:`)은 그 턴의 모든 글에서 찾는다. 물음표 줄(신호 4)은 마지막 답에서만 찾는다. (결정 2026-11-15, 실화면 5번 X 뒤)
- 합치는 규칙:
  1. 신호 1~3의 줄을 모두 모은다. 첫 줄이 `question`, 나머지가 `background`다.
  2. 색은 가장 급한 것이다 (결재 > 알림). 선택 카드나 질문 상자의 질문이 `결재:`로 시작해도 결재다. (결정 2026-11-15, Q2)
  3. 신호 4는 신호 1~3이 모두 없을 때만 쓴다.
  4. 코드 울타리(```) 안의 줄은 보지 않는다.
  5. `확인:` 줄은 확인 칸에 더한다. 같은 글의 줄은 더하지 않는다. 확인 칸이 `closed`이면 빈 목록에서 새로 시작한다.
- 부르는 때:

| 때 | 동작 |
|---|---|
| `turn.complete`, `reason: answer`, 하위 에이전트 아님 | `sync()`. 신호가 없으면: 사용자 입력으로 시작한 턴이면 `closed`, 아니면 그대로 둔다 (D4) |
| `turn.complete`, `reason: aborted · error · refusal` | 다시 판정하지 않는다. `busy`이면 `waiting`으로 되돌린다 |
| `session.start` (세션 시작, 다시 열기, mod 다시 읽기) | `sync()` |
| `prompt.submit`, 사용자 출처 | 기다림 칸이 `waiting`이면 `busy` |
| `session.end`, 이유 `prompt_input_exit · clear · logout` | 기다림 칸을 `closed`. 확인 칸은 그대로 (D2) |
| `session.end`, 이유 `other · resume` | 그대로 둔다 (앱 종료, 이어받기) (D2) |
| 선택 카드 `tool.call` | `next` 앞에 `waiting`, `await next` 뒤에 `busy`. 파일 쓰기 실패는 도구 호출을 막지 않는다 |

### 7.3 알림 (R8)

- 이 프로젝트의 칸이 새로 `waiting`이 되면 패널을 열고 알림을 1번 띄운다.
- 알림 키는 `id + raisedAt`이다. 같은 세션의 두 번째 기다림도 다시 알린다.

## 8. AI의 규칙 (R9)

1. 사용자의 답이 필요하면 대화에 자료와 질문을 쓴다. 평소처럼 묻는다.
2. 되돌리기 어려운 결정이면 질문 앞에 `결재:`를 쓴다 (답의 줄, 선택 카드의 질문, 질문 상자의 질문).
3. 답이 필요한데 물음표로 끝나지 않는 요청이면 그 줄 앞에 `알림:`을 쓴다 (예: 노력 수준 변경 요청).
4. 추천안으로 이미 진행했으면 그 줄 앞에 `확인:`을 쓴다.
5. 결재의 답은 자기 프로젝트의 `docs/결정_기록.md`에 쓴다. 없으면 만든다. 양식: `| 날짜 | 질문 | 답 (원문) |`.

없애는 것: 결정 파일 쓰기·지우기·다시 올리기, 노력 수준 칸의 파일 양식 (3번으로 대신), 작업 세션 시작 때 결재함 정리.

## 9. 총괄 세션과 하위 세션

- 총괄 세션: 사용자가 프로젝트 전체를 지휘하는 세션. 하위 세션: 총괄 세션이 일을 나눠 연 세션. 둘 다 앱의 세션이고 각자 mod가 돈다.
- 하위 에이전트(세션 안의 `Agent` 도구)는 세션이 아니다. 그 턴은 판정하지 않는다.
- 사용자는 결재함에서 하위 세션의 칸을 보고 그 세션으로 가서 답한다. 총괄 세션은 결과를 문서로 받는다.

## 10. 실패하는 경우 (R10)

| 경우 | 동작 | 대책 | 남는 위험 |
|---|---|---|---|
| AI가 신호 없이 기다린다 | 신호 4가 잡는다 | 8절 3번 (`알림:`) | 물음표도 표시도 없는 요청은 놓친다 |
| AI가 `결재:`를 잊었다 | 노랑 칸이 된다 | 8절 2번 | 급한 결정이 덜 급하게 보인다 (옛 `kindOf`는 반대였다) |
| 다른 일을 시켜 앞 질문이 답에 없다 | 다음 턴 끝에 `closed` | 없음 (AI 기억에 기대지 않는다) | 앞 질문이 결재함에서 사라진다 |
| 탐지가 틀렸다 (헛칸) | 다음 턴 끝에 다시 판정 | — | 그 세션의 다음 턴까지 칸이 남는다 |
| 사용자가 턴을 중단했다 | `busy` → `waiting` | — | 없다 |
| 세션을 보관했다. 세션이 강제로 끝났다 | 이유가 앱 종료와 같은 `other`라 칸을 남긴다 | 알림 칸에 `닫기` 단추. 결재 칸에는 두지 않는다 (결정 2026-11-16) | 보관한 세션의 결재 칸은 그 세션을 다시 열어 답할 때까지 남는다 |
| 앱을 껐다 켰다 | 칸을 남긴다 (D2). 연 세션은 `session.start`에서 다시 판정 | 칸에 시간(`raisedAt`)을 보인다 | 열지 않은 세션의 칸은 낡을 수 있다 |
| 같은 앱 세션이 새 세션 번호를 받았다 (이어받기 등) | 새 번호의 판정이 같은 링크의 옛 번호 기다림 칸을 `closed` (결정 2026-11-15, 실화면 중 발견) | 다른 세션 안에서 띄운 세션(`CLAUDE_CODE_SESSION_ID`가 자기 번호와 다르다)은 앱 링크를 쓰지 않는다. 그래서 부모의 칸을 닫지 않는다 (2026-11-15 실제 확인) | 없다 |
| `/clear` | 기다림 칸 `closed`. 새 세션 번호로 이어진다 | — | 새 번호의 칸은 다음 턴 끝까지 없다 (`/clear` 뒤 `session.start`가 오지 않는다) |
| 확인을 누르는 순간 그 세션의 턴이 끝났다 | 주인 mod가 덮어쓴다 | — | 드물게 확인한 칸이 다시 보인다 |
| 닫힌 파일이 쌓인다 | 세션마다 2개 | 세션 시작 때 7일 넘게 닫힌 파일을 `cmd /c del`로 지운다 (2026-11-16 구현). 경로에 cmd 특수 글자가 있으면 지우지 않는다 | 집 폴더 이름에 영문 밖의 글자가 있으면 정리가 꺼진다 |
| mod 없이 시작한 세션 | 칸이 생기지 않는다 | `/reload-plugins` | 그 세션은 결재함에 보이지 않는다 |
| 대화 압축 중 | 턴 끝에 칸을 쓴다 | — | 없다 (문제 5가 사라진다) |
| 다른 PC | 저장소의 mod를 설치한다 | — | PC마다 결재함이 따로다 |

## 11. 정한 질문 (R11)

| # | 질문 | 결정 | 버린 안과 이유 |
|---|---|---|---|
| Q0 | 칸은 언제 사라지는가 | 턴이 끝날 때 다시 판정. 세션마다 1개 | AI가 지운다 (잊는다) / 입력하면 사라진다 (답인지 모른다) |
| Q1 | 누가 칸을 만드는가 | mod가 대화에서 뽑는다 | AI가 파일을 쓰고 mod가 일생만 관리 (원본 2개, 도구 호출 유지) |
| Q2 | 빨강은 무엇으로 정하는가 | `결재:` 표시만 | 선택 카드·멈춤 표시도 빨강 (빨강이 너무 많다) |
| Q3 | 입력하면 칸은 어떻게 보이는가 | 흐리게, "진행 중" | 숨긴다 (긴 작업 중 안 보인다) / 그대로 (답한 칸과 구별 없음) |
| Q4 | 끝난 칸의 파일 | ~~mod가 지운다~~ → 지우지 않고 `closed`로 덮어쓴다 (D1) | 셸 `del`로 지운다 (명령 주입, 거짓 성공, 1.5초 제한) |
| Q5 | 초록 확인 칸 | 남긴다 | 없앤다 (혼자 정한 것을 놓친다). 확인용 별도 파일 (1인용에 지나치다) |
| Q6 | 물음표 탐지 | 남긴다. 물음표 줄만 | 없앤다 (터미널 세션을 놓친다) / "쉬는 세션" 묶음 (새 UI) |
| D2 | 세션 종료 | 사용자가 끝낸 경우만 닫는다 | 모든 종료에 닫는다 (앱을 껐다 켜면 모두 사라진다) |
| D3 | 새 파일 위치 | `decisions/v2/` | 같은 폴더 (옛 mod가 새 파일을 빨강으로 잘못 읽는다) |
| D4 | 사용자 입력이 아닌 턴 | 칸을 닫지 않는다 | 닫는다 (답하지 않았는데 사라진다) |

### 12.3 시험 (`claude plugin test <mod 폴더>`)
1. `결재:` 줄 → `waiting`, `request`
2. `알림:` 줄 → `notice`
3. 끝 줄 `?`, 다른 신호 없음 → `notice`. `결재:`가 있으면 `?` 줄을 쓰지 않는다
4. `확인:` 줄 → 확인 칸에만. 같은 줄은 두 번 더하지 않는다
5. 사용자 입력 턴이 신호 없이 끝남 → `closed`
6. 사용자 입력이 아닌 턴이 신호 없이 끝남 → 그대로
7. 하위 에이전트의 턴 → 그대로
8. 사용자 출처 입력 → `busy`. `task-notification` 출처 → 그대로
9. 중단된 턴 → `busy`가 `waiting`으로
10. `session.end` `prompt_input_exit` → 기다림 칸만 `closed`. `other` → 그대로
11. `session.start` → 마지막 답으로 다시 판정
12. 선택 카드 `next` 앞 `waiting`, 뒤 `busy`
13. 패널: `closed` 숨김, `busy` 흐림, 상태 줄 개수에서 `busy` 제외, "확인" → 확인 칸 `closed`
14. 같은 id에 `raisedAt`이 바뀌면 다시 알린다
15. `v2/` 밖의 파일과 이름 모양이 다른 파일은 읽지 않는다
16. 코드 울타리 안의 `결재:`는 신호가 아니다

### 12.6 완료 조건 (실화면)
1. 세션 A가 `결재:`로 끝난다 → 세션 B의 패널에 빨강 칸, 알림 1번
2. A에 입력한다 → B에서 흐려지고 상태 줄 개수가 준다
3. A의 다음 답에 신호가 없다 → 칸이 사라진다
4. 선택 카드를 띄운다 → 칸이 생긴다. 답한다 → 흐려진다
5. `확인:` → 초록 칸. B에서 "확인" → 사라진다
6. 앱을 껐다 켠다 → A의 칸이 남아 있다
7. 터미널 세션이 `?`로 끝난다 → 칸이 생긴다
8. 칸을 누른다 → 그 세션으로 이동한다

## 13. 하지 않는 것 (R13)

- 결재함에서 답하는 버튼.
- 입력이 질문의 답인지 mod가 판단하는 일.
- 답의 번호 목록을 선택지로 읽는 일. 결재 칸은 질문과 배경 줄만 보인다.
- 명령 주입 대비, 확인용 별도 파일, 옛 파일을 흐리게 보이기, 남의 오래된 파일 지우기, "쉬는 세션" 묶음 (EGM 8단계 판단: 1인용에 지나치다).
